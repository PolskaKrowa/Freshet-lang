### fsht-03:01-05.04.01 — numeric text parsing

Status: normative (fsht-03:01). Spec:
[spec/23-stdlib-expansion.md](../../spec/23-stdlib-expansion.md) §1.
Reference implementation: Penstock 0.1.0-INDEV (conformance:
corpus `tests/corpus/20_stdlib_parsing_streaming.fsht`, props
`tests/props/p08_stdlib_numeric.fsht`, fuzz `b_parse` block here;
negative `n30_checked_mixed_width` / `n31_parse_not_str` for the
type rules).

`parse_i64` / `parse_u64` / `parse_f64` — the counterpart of the
formatting functions, one of fsht-01:01's most important omissions.
**Ratified surface (fsht-03:01):** each takes a `str`, returns
`Result<T, ParseError>` over the new prelude enum `ParseError { Invalid,
OutOfRange }`; leading/trailing ASCII whitespace is skipped; integer
overflow reports `Err(OutOfRange)` rather than wrapping; `parse_f64`
accepts the full `fmt_f64` round-trip grammar (`inf`/`-inf`/`nan`,
exponents); and the round-trip law `parse_i64(str_of(&fmt_i64(x))) ==
Ok(x)` is MUST-level. Narrower-width parsing composes as
`parse_i64` + `checked_cast` (ch. 23 §7 deferral).

History:
- fsht-03:01 (accepted) — first accepted.
- fsht-03:01 (ratified 2026-11-19) — chapter 23 §1 normative; the
  `ParseError` prelude enum, the whitespace rule and the round-trip
  law are part of the ratified surface. Narrower `parse_i8` family
  ratified as a deliberate deferral (composition covers it).

### fsht-03:01-05.05.01 — streaming I/O with `Result` integration

Status: normative (fsht-03:01). Spec:
[spec/23-stdlib-expansion.md](../../spec/23-stdlib-expansion.md) §4.
Reference implementation: Penstock 0.1.0-INDEV (conformance: corpus
`tests/corpus/20_stdlib_parsing_streaming.fsht` — write/stream-read/
line-read round-trip; negative `n29_reader_use_after_close` for the
handle lifecycle; the target matrix runs the stream smoke per target,
registry 10.03.02).

Files, streams and buffered readers/writers; `Result<T, E>`
integration so failures propagate instead of surfacing as ambiguous
empty values. **Ratified surface (fsht-03:01):** prelude structs
`Reader { handle: i64 }` / `Writer { handle: i64 }` and prelude enum
`IoError { NotFound, Permission, Eof, Busy, Other(i64) }`; module
`io` functions `reader_open`, `reader_stdin`, `reader_read` (buffered
fill into a `Span<u8>` out-region, `Ok(0)` = EOF), `reader_read_line`
(owned `String`, `Err(Eof)` at end), `writer_open`, `writer_write`,
`writer_flush`, `reader_close` / `writer_close`, `remove`; handles
are ownership-tracked resources (scope-exit close, close as
pre-emptive release, use-after-close `F0301`); readers/writers MUST
buffer (64 KiB default SHOULD-level).

History:
- fsht-03:01 (accepted) — first accepted.
- fsht-03:01 (ratified 2026-11-19) — chapter 23 §4 normative with the
  handle-ownership model; `file_read`'s whole-file contract (ch. 18)
  unchanged. `reader_stdin`'s per-target behaviour is fixed by the
  fsht-03:03 runtime chapter.

### fsht-03:01-05.06.01 — standard-library decomposition

Status: normative (fsht-03:01). Spec:
[spec/23-stdlib-expansion.md](../../spec/23-stdlib-expansion.md) §5.
Reference implementation: Penstock 0.1.0-INDEV.

The `fsh` module grows into a proper collection of reusable modules:

```
core         primitive operations, memory, assertions
alloc        allocators, buffers, vectors
collections  vectors, queues, maps, sets
string       UTF-8 strings and formatting
math         standard mathematical functions
io           files, streams, buffered readers/writers
numeric      numeric traits and common algorithms
time         duration, timestamps and timers
bits         bit manipulation, endian conversion
random       random-number generators
```

The language stays independent of the scientific libraries (the
three-layer rule of spec ch. 00): a developer can write a plain CLI
application without importing half a physics framework, and the
numerical library can evolve without compiler changes for every new
algorithm.

**Ratified surface (fsht-03:01):** the ten modules ship in the builtin
modules directory with the minimum normative content of ch. 23 §5
(`core` assertions + intrinsics; `string` ch. 10 builtins + parse;
`collections` the `vec_*` surface; `math` the ch. 13 intrinsics;
`numeric` the variant/conversion functions + `abs`/`gcd`/`clamp`;
`bits` `bswap16/32/64` + `popcount`; `io` §4's streaming surface;
`time` `now_ns`/`now_ms`; `alloc` `page_size`; `random`
`sm64_next(&mut u64)` — the xorshift64\* generator the fuzz and
benchmark harnesses use, so streams are reproducible across
implementations). The layer-separation rule and the unchanged `fsh`
façade are MUST-level. Queue/map/set container types, custom
allocators, calendar time and async I/O remain deferrals.

History:
- fsht-03:01 (accepted) — first accepted with the layer-separation
  requirement stated.
- fsht-03:01 (ratified 2026-11-19) — chapter 23 §5 normative; the
  module skeleton is the ratified surface, new container types are
  explicitly deferred (not silent omissions).
