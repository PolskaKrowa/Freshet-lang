### fsht-03:01-05.05.01 — streaming I/O with `Result` integration

Status: accepted (target fsht-03:01). Spec: —

Files, streams and buffered readers/writers; `Result<T, E>` integration
so failures propagate instead of surfacing as ambiguous empty values.
Reading an entire multi-gigabyte dataset into a single `String` is not
a viable scientific-computing strategy — the library must stream.

History:
- fsht-03:01 (accepted) — first accepted.

### fsht-03:01-05.06.01 — standard-library decomposition

Status: accepted (target fsht-03:01). Spec: —

The `fsh` module grows into a proper collection of reusable modules:

```
core         primitive operations, memory, assertions
alloc        allocators, buffers, vectors
collections  vectors, queues, maps, sets
string       UTF-8 strings and formatting
math         standard mathematical functions
io           files, streams, buffered readers/writers
numeric      numeric traits and common algorithms
time         duration, timestamps and timers
bits         bit manipulation, endian conversion
random       random-number generators
```

The language stays independent of the scientific libraries (the
three-layer rule of spec ch. 00): a developer can write a plain CLI
application without importing half a physics framework, and the
numerical library can evolve without compiler changes for every new
algorithm.

History:
- fsht-03:01 (accepted) — first accepted with the layer-separation
  requirement stated.
